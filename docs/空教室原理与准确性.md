# 空教室原理与准确性

## 一、算法

```
空教室 = 教室全集 − 该时段被占用的教室
```

「教室全集」= `data/classrooms.js` 里所有 `openForStudy !== false` 的教室。

「被占用」由两个数据源合并计算：

| 来源 | 数据 | 能看到什么 | 缺失的后果 |
|---|---|---|---|
| ① 我的课表 | `data/courses.js` | 只包含**你自己**的课占用 | 别的班级占用同一间教室你不知道 |
| ② 全校占用表 | `data/occupancy.js` | 所有登记课程的教室占用 | 未登记的临时借用、讲座、补课看不到 |

判定流程（`utils/classroom.js`）：

1. 由查询日期算出**第几周**（`termStartDate` 基准）和**星期几**
2. 遍历两个数据源，筛出：星期匹配 + 该周次有效（含单双周判断）+ 节次与查询区间有交集
3. 按教室汇总成 `busy[roomId][period] = { name, source }` 的占用索引
4. 对每间教室，计算当天的**空闲段列表**（连续未占用的节次区间）
5. 查询区间 `[start, end]` 完全落在某个空闲段内 → 判定为空闲
6. 再按楼栋 / 座位数 / 设施 / 是否允许自习 过滤，最后排序输出

## 二、查询结果里的两个字段

| 字段 | 示例 | 含义 |
|---|---|---|
| `freeSpanText` | `第5-6节 空` | 你查询的这段确实是空的 |
| `runSpanText` | `可连用 第1-10节（7 小时 30 分钟）` | 这间教室今天能连续用到什么时候 |

这样既能确认"现在有座"，又能判断"能不能安心坐一下午"。

## 三、准确性分级

| 情况 | 准确性 | 页面提示 |
|---|---|---|
| 只导入自己的课表 | ⚠️ 偏低，结果偏多 | 顶部橙色警告 |
| 导入了全校占用表 | ✅ 较好，与教务排课一致 | 无警告 |
| 存在课表未登记的教室编号 | ⚠️ 这些教室会被漏掉 | 顶部警告并列出编号 |

**建议**：能拿到全校课表就用「设置 → 数据管理 → 导入备份」导入，
或者在 `data/occupancy.js` 里把已知的长期占用手写进去。

## 四、已知局限

1. **临时占用无法感知**：讲座、补课、教室临时借用、考试占用都不会体现在数据里。
   最稳妥的做法是到了教室门口看一眼，或提前问一下助教。
2. **教室字典需要手工维护**：新增教学楼、改编号后记得同步 `data/classrooms.js`。
3. **自习室的开放时间不是课表能表达的**：图书馆自习室的开关门时间、
   四六级考试封楼等属于「非课程占用」，当前版本没有建模。
   如果学校有固定封楼安排，可以往 `occupancy.js` 里加一条全天占用记录来模拟。
4. **不区分"这间教室虽然空但被锁了"**：数据层无法表达物理门禁状态。

## 五、如何提升准确性（按性价比排序）

1. 导入全校占用表（收益最大）
2. 补齐教室字典，保证课表里的每个 `roomId` 都能对应上
3. 把已知的长期占用（如某实验室每周三晚上有课）手写到 `occupancy.js`
4. 每次开学核对一次节次作息表 `periods.js` 和开学日期 `TERM.startDate`
