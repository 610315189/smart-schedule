# 文件导入说明（Excel / Word / CSV）

小程序支持直接导入教务系统导出的课表文件，**全部在本机解析，文件不会上传到任何服务器**。

---

## 一、支持的文件类型

| 扩展名 | 支持 | 说明 |
|---|---|---|
| `.xlsx` | ✅ | Excel 2007+，推荐格式 |
| `.docx` | ✅ | Word 2007+，表格或正文均可 |
| `.csv` | ✅ | 建议保存为「CSV UTF-8」 |
| `.txt` | ✅ | 每行一条课程 |
| `.xls` | ❌ | 1997 年二进制格式，请另存为 `.xlsx` |
| `.doc` | ❌ | 同上，请另存为 `.docx` |
| `.pdf` / 图片 | ❌ | 本版本不支持 |

> 为什么 `.xls` / `.doc` 不支持：它们是早期 Office 的 OLE2 复合文档格式，不是 ZIP 包，
> 解析器完全不同。小程序端做不了，也不值得做——用 Office/WPS 打开另存一次即可。

**怎么把文件给到小程序**：`wx.chooseMessageFile` 只能读取微信聊天记录里的文件。
所以先把课表发到「文件传输助手」，再在小程序里「课表 → 批量导入 → 选择文件」中选它。

---

## 二、智能识别：程序是怎么找到课表的

真实的教学文件往往很"脏"——前面有标题和学号，中间夹杂空行，表头写法五花八门，
甚至压根没有表头。所以导入不是"按固定格式解析"，而是走了四步推理。

### 第 1 步：定位课表区域

把整张表按"连续的非空行"切成若干数据块（允许块内有少量空行），
再对每个块分别尝试识别，最后挑最像课表的那一块。于是下面这些都能正确处理：

```
XX大学 2026-2027 学年第一学期 学生个人课表      ← 标题，跳过
学号：2026001  姓名：张三  专业：计算机科学       ← 说明，跳过
打印时间：2026-09-01                            ← 跳过
                                               ← 空行，跳过
序号  科目     星期   上课时间  教学地点  周次     ← 真正的表头
1    高等数学  星期一  1-2      A301     1-16周
...
注：以上课程如有调整，以教务处通知为准。          ← 备注，跳过
```

### 第 2 步：判断布局

| 判据 | 判定结果 |
|---|---|
| 某一行里"星期"占非空单元格的比例 ≥ 50%，且至少 3 个星期 | 是课表网格，这一行是星期表头 |
| 某一行能匹配上 ≥ 3 个字段名，且含课程名与时间类字段 | 是列表式，这一行是表头 |
| 都不满足 | 改为按列内容推断（第 3 步的 B 方案） |

### 第 3 步：对齐每一列

三种方式，按可信度从高到低：

**A. 认表头**（最可靠）——不是死记硬背，而是模糊匹配：

| 你写的表头 | 识别为 |
|---|---|
| `科目` / `课程` / `教学班名称` / `课程名字` | 课程名 |
| `星期` / `周几` / `上课星期` | 星期 |
| `节次` / `上课节次` / `节数` | 节次 |
| `上课时间` / `时段` / `时间` | 时间（自动换算成节次） |
| `教学地点` / `上课教室` / `地点` | 教室 |
| `周次` / `起止周` / `上课周` | 周次 |
| `授课教师` / `任课教师` / `老师` | 教师 |

表头分两行写（第一行大类、第二行细分）时，会把两行合并成复合表头再匹配。

**B. 不看表头，看列里的内容**——给每一列做"内容画像"：

```
第 1 列：5 个值都含中文、平均长度 6.2、不含其它特征   → 课程名
第 2 列：5/5 都能解析成星期                       → 星期
第 3 列：5/5 都能解析成节次 "1-2" / "3-4"          → 节次
第 4 列：5/5 都命中教室字典                       → 教室
第 5 列：5/5 都含"周"                             → 周次
第 6 列：5/5 都是 2-4 字纯中文                     → 教师
```

所以**没有表头、甚至列顺序被打乱**也能正确对齐。

**C. 两者结合**：先让特征最鲜明的列（星期/周次/节次/教室）占位，剩下的再定课程名。

### 第 4 步：多方案打分选优

上面会产生多个候选解释（不同区域 × 不同布局 × 不同起始行）。每个候选都**真实提取一遍**，再打分：

| 因素 | 影响 |
|---|---|
| 提取到的课程条数 | 加分（有封顶，防止大表碾压） |
| 平均字段完整度（星期/节次/教室/周次/教师齐全程度） | 加分 |
| 识别来源：有表头 > 有网格 > 纯内容推断 | 加分 |
| 同一门课在同一天被切成多条 | **扣分**（通常说明结构认错了） |

得分最高的方案胜出。整个过程是确定性的，同一个文件每次结果一致。

### 识别结果会告诉你"我看到了什么"

预览区顶部会显示识别依据，不是黑箱：

```
✓ 识别出 5 门课程（布局：列表式）
🔍 识别到表头（第 5 行，占 2 行）
   字段完整度：100%
```

无表头时会列出推断依据：

```
🔍 按内容特征推断（无表头）
   无表头，按列内容推断：课程名=第1列、星期=第2列、节次=第3列、教室=第4列、周次=第5列
   字段完整度：100%
```

每条课程也会标注 `字段完整` 或 `需确认 80%`（80% 表示 5 个关键字段里缺了 1 个）。

## 三、能识别的两种课表布局

导入时会自动判断布局，不需要手动选。

### 布局 A：列表式

每行一门课，第一行是表头。

| 课程名称 | 星期 | 节次 | 教室 | 周次 | 教师 |
|---|---|---|---|---|---|
| 高等数学(上) | 星期一 | 1-2 | A301 | 1-16周 | 张建国 |
| 大学英语(II) | 周一 | 3-4节 | A401 | 1-16周 | 李雯 |
| 大学物理 | 星期四 | 第7-8节 | A201 | 1-16周(单) | 周立 |

**表头别名**（以下写法都能认出来，大小写不敏感、支持括号后缀）：

| 字段 | 可识别的表头写法 |
|---|---|
| 课程名 | 课程名称、课程名、教学班名称、课程、科目、名称 |
| 星期 | 上课星期、星期几、星期、周几、上课日 |
| 节次 | 上课节次、节次、节数、课节 |
| 时间 | 上课时间、时间段、时间、时段（会自动换算成节次） |
| 教室 | 上课地点、上课教室、教学地点、授课地点、教室、地点、课室 |
| 周次 | 上课周次、起止周、周次、周数、上课周 |
| 教师 | 任课教师、授课教师、教师姓名、教师、老师 |

### 布局 B：网格式（教务系统最常见的课程表）

上方一行是星期，左侧是节次，格子里写课程信息。

| 节次 | 星期一 | 星期二 | 星期三 | 星期四 | 星期五 |
|---|---|---|---|---|---|
| 1-2节 | 高等数学(上)<br>张建国<br>A301<br>1-16周 | | 数据结构<br>刘伟<br>B301<br>1-16周 | | |
| 3-4节 | | 大学英语(II)<br>李雯<br>A401<br>1-16周 | | 大学物理<br>周立<br>A201<br>1-16周(单) | |
| 5-6节 | 程序设计基础<br>刘伟<br>A301<br>1-16周 | | | | 计算机网络<br>郑楠<br>B201<br>1-16周 |

**合并单元格会被正确处理**：

| 课表长这样 | 导入结果 |
|---|---|
| 节次列合并成 `1-2节`（一个格子跨两行） | 得到 1-2 节 |
| 课程格子跨行合并（`第1节`、`第2节` 两行都显示同一门课） | 自动合并成一门 1-2 节的课，不会重复 |
| 首列没写节次，只靠课程格跨行 | 按行位置推出节次并合并相邻区间 |

### 布局 C：Word 纯正文

Word 里没有表格时，按每行一条解析：

```
高等数学(上),周一,1,2,A301,1-16
程序设计基础 周三 5-6节 A301 1-16周
大学物理 周四 7-8节 A201 1-16周单
```

字段顺序不限，只要能认出星期、节次、教室、周次即可。

---

## 四、单元格内容的识别规则

一个格子里写「高等数学(上) / 张建国 / A301 / 1-16周」时，解析器按下面的顺序抽取：

1. **周次**：`1-16周`、`第1-16周`、`1~16周`、`3-12`、`1,3,5,7周`、`1-16周(单)`、`2-16双周`
2. **教室**：优先匹配 `data/classrooms.js` 教室字典里的编号（**最可靠**），
   其次是 `地点：A301` 这类关键词，最后用常见编号模式（`A301`、`一教101`、`实验楼C105`、`3-201`）
3. **课程名**：剩余的第一段文本
4. **教师**：出现在课程名之后的 2-4 个纯汉字

**一个格子写两门课**（如"单周上 A、双周上 B"）也能拆开——检测到两个以上周次写法时，
会按周次位置切分，每段一门课。

## 五、导入后会看到什么

解析完成后先给**预览**，不会直接写入课表：

```
✓ 识别出 6 门课程（布局：课表网格）
· 文件包含 2 个工作表，已自动选用「2026秋课表」
· 教室字典中没有：D501（这些教室不会出现在空教室结果里）

星期一 1-2节 · A301 · 张建国 · 1-16周
星期三 1-2节 · B301 · 刘伟 · 1-16周
星期一 5-6节 · 未识别 · 刘伟 · 1-16周    ⚠ 未识别到教室
```

- 标了「需确认」橙色标签的条目，表示有字段没识别出来（会填默认值）
- 预览最多显示 60 条，但**导入时会写入全部**
- 点「确认导入」后可选「追加到现有课表」或「替换整个课表」

导入后仍可在「课表 → 课程列表」里逐条修改，或直接删掉重新导。

## 六、识别不准怎么办

按性价比排序：

1. **补齐教室字典**（`miniprogram/data/classrooms.js`）
   教室识别优先走字典匹配，字典全了识别率会明显提高。
2. **简化单元格内容**
   把「高等数学(上)(必修)(王老师)(1-16周)(A301)」这种堆在一起的写法拆成多行，识别率最高。
3. **改用列表式**
   如果教务系统能导出"每行一门课"的表，优先用它，比网格课表好解析得多。
4. **在预览里找出问题条目**
   带 ⚠ 的条目就是没识别好的，导入后手工改这几条即可。
5. **导出成 CSV 自己整理**
   Excel 里把列顺序调成「课程名称,星期,节次,教室,周次」，再另存为 CSV UTF-8 导入。

## 七、编码问题

| 情况 | 表现 | 解决 |
|---|---|---|
| Excel 的 `.xlsx` / Word 的 `.docx` | 不会乱码 | 内部固定 UTF-8 |
| CSV 用 UTF-8 / UTF-8 BOM 保存 | 正常 | 推荐 |
| CSV 用 GBK / ANSI 保存 | 中文变乱码 | 页面会提示；请另存为「CSV UTF-8」 |

## 八、技术实现（为什么纯前端也能读 Excel）

`.xlsx` 和 `.docx` 本质上都是 **ZIP 压缩包**，里面装着 XML。所以整条链路是：

```
选文件 → 读字节 → 识别 ZIP → 解析中央目录 → 逐条 DEFLATE 解压（CRC32 校验）
      → 解析 XML → xlsx：共享字符串/内联字符串 + 合并单元格 → 二维表格
                 docx：w:tbl 表格 + vMerge 纵向合并 + w:p 段落
      → 结构识别（列表式表头 / 网格式网格）→ 单元格内容解析 → 课程对象
```

相关文件：

| 文件 | 职责 |
|---|---|
| `utils/inflate.js` | 纯 JS 实现 DEFLATE 解压（RFC 1951）+ CRC32，不依赖平台 API |
| `utils/zip.js` | ZIP 容器解析：中心目录、本地头、条目读取、CRC 校验 |
| `utils/xml.js` | 轻量 XML 解析器（小程序没有 DOMParser），支持命名空间与实体 |
| `utils/bytes.js` | UTF-8 解码、小端整数读取 |
| `utils/xlsx.js` | Excel：sharedStrings / inlineStr / 布尔 / 数字 / 合并单元格 |
| `utils/docx.js` | Word：表格、gridSpan、vMerge 继承、段落换行 |
| `utils/schedule-extract.js` | 课表结构识别：表头模糊匹配、网格提取、单元格内容解析 |
| `utils/table-detect.js` | 智能识别：课表区定位、列画像、无表头推断、多方案打分 |
| `utils/file-import.js` | 类型识别与调度，统一的导入入口 |

**为什么不用 `wx.getFileSystemManager().unzip()`**：该 API 在 iOS 上不可用，
且会把解压结果落盘，多一步 IO。自己实现 inflate 后，Android / iOS / 开发者工具行为完全一致。

`utils/inflate.js` 的正确性由 `tools/test-inflate.js` 与 Node 内置 `zlib` **逐字节交叉验证**
（含中文、随机二进制、64KB 数据、空数据、各压缩级别、zlib/gzip 包装）。

## 九、隐私

- 文件在你的手机上被解析，**不会上传**
- 只有当你主动点「设置 → 上传课表」时，课表才会发往你自己部署的服务器
- 解析用的是内存中的字节，不写任何临时文件

## 十、已实测的教务系统导出格式

下面这些"很不好解析"的写法已经实测通过，样本文件放在 `tools/samples/sample-jwxt-real.xlsx`
（真实教务系统导出，作为回归样本保留）。

| 特征 | 长什么样 | 处理方式 |
|---|---|---|
| **竖排连写的节次** | `第\n一\n二\n节`（每字一行），表示第 1-2 节 | 去掉"第/节"后得到"一二"，还原为 1-2；`第五六节`→5-6、`第九十节`→9-10 |
| **单元格用 ◇ 分隔** | `高等数学I◇4-17(1,2节)◇经管教学楼308◇敖国艳` | 按 `◇ ◆ ● ○ ■ □ · ・` 等符号分段，逐段识别 |
| **周次省略"周"字** | `4-17` 而不是 `4-17周` | 先按带"周"的标准写法匹配，失败再接受省略写法 |
| **教室名被简写** | `综合602安博实验室一`（没有"楼"字） | 除"XX楼/馆/中心"外，再补一条"中文简称 + 3~4 位房间号"的模式 |
| **教室带功能后缀** | `科技楼117机房`、`综合楼603安博实验室二` | 取前面的编号作教室，后面的"机房/实验室"不并入课程名 |
| **表头在标题下方** | 第 1 行"班级课程表"、第 2 行班级信息，第 3 行才是星期 | 区域切块 + 表头定位自动跳过前两行 |
| **周六周日也有课** | 星期表头一直排到"星期日" | 7 天全部识别 |
| **同一天连堂** | 周六 5-6 节和 7-8 节是同一门课 | 合并成一门 5-8 节的课，不会记两条 |

### 教室字典一键补充

导入后如果发现课表里的教室不在教室字典中，预览区会出现一条黄色提示：

```
⚠ 有 8 间教室不在教室字典里：经管教学楼308、综合楼603、综合602、……
不补进字典的话，这些教室不会出现在「空教室」查询结果里。
[一键加入教室字典]
```

点一下会自动创建这些教室（楼栋与楼层从编号推断：`经管教学楼308` → 楼栋"经管教学楼"、3 楼），
无需手工编辑 `classrooms.js`。座位数未知的会显示为"座位未知"，你可以之后在
`data/classrooms.js` 里补上真实容量。

> **为什么必须补**：空教室查询的"教室全集"来自教室字典。字典里没有的教室，
> 即使课表里出现了，查询时也不会把它们算进去——要么漏掉一间可用的空教室，
> 要么算出一间其实有课的教室。
