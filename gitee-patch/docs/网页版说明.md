# 网页版说明（H5 · 扫码即用）

把原来的微信小程序改成**普通网页**：手机浏览器扫码打开，不需要 AppID、不需要审核、不需要上传到微信。

核心算法（课表引擎、空教室反查、Excel/Word 课表解析）与小程序版**共用同一份源码**，
所以两边算出来的课表、空教室结果完全一致。

---

## 一、三种用法

### 方式 1：本机跑起来，局域网扫码（最快，1 分钟）

```bash
node tools/serve-web.js
```

启动后终端会打印：

```
本机访问：http://localhost:8080
局域网访问：http://192.168.1.10:8080   （WLAN）  ← 推荐（手机扫这个）
```

然后生成二维码：

```bash
node tools/make-qrcode.js
```

会得到 `qrcode-lan.png`。手机连**同一个 WiFi**，用相机或微信扫码即可打开。

> 换端口：`PORT=9000 node tools/serve-web.js`
> 换地址：`node tools/make-qrcode.js --url http://192.168.1.10:8080/`

### 方式 2：部署到公网（同学在任何地方都能扫码）

产物是**纯静态文件**，放到任何静态空间即可，不需要 Node 环境。

**A. 自有服务器 / 宝塔面板**

把 `web/` 目录整个上传到站点根目录，Nginx 配置：

```nginx
server {
    listen 443 ssl;
    server_name schedule.example.com;
    root /www/wwwroot/schedule;
    index index.html;

    # PWA 需要
    location = /sw.js {
        add_header Cache-Control "no-cache";
    }
    # 单页应用：找不到文件就回首页
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

**B. GitHub Pages / Cloudflare Pages / Vercel / Netlify**

- 仓库里把 `web/` 目录设为发布目录（GitHub Pages 可用 `gh-pages` 分支或 Actions）
- 这些平台自动提供 HTTPS，PWA（添加到主屏幕 + 离线）会直接生效
- 部署完把平台给你的网址发给同学，或自己生成二维码：
  `node tools/make-qrcode.js --url https://你的域名/`

**C. 只用单文件版（最省事）**

```bash
node tools/build-standalone.js
```

生成 `web/standalone.html`（约 260KB，**CSS/JS/图标全部内联**）。
把这**一个文件**上传到哪里都能用，也可以直接发微信文件给同学——对方下载后用浏览器打开即可。

> 注意：单文件版用 `file://` 打开时，浏览器会限制部分能力（Service Worker 不可用），
> 但课表、空教室、导入、导出日历都正常工作。

### 方式 3：装到手机主屏幕（像 App 一样）

部署到 **HTTPS** 或 `localhost` 后：

- **iPhone / iPad**：Safari 打开 → 分享 → 「添加到主屏幕」
- **Android**：Chrome 打开 → 右上角菜单 → 「添加到主屏幕」

添加后从桌面图标启动，没有浏览器地址栏，体验接近原生 App，并且**离线可用**
（Service Worker 会缓存页面与文件）。

> 局域网 `http://192.168.x.x` 访问时，浏览器不允许注册 Service Worker，
> 所以"添加到主屏幕"和离线缓存只在 HTTPS 下生效。

## 二、功能对照：小程序版 vs 网页版

| 能力 | 微信小程序版 | 网页版 |
|---|---|---|
| 今日课表 / 倒计时 | ✅ | ✅ |
| 周课表网格 | ✅ | ✅ |
| 空教室查询 | ✅ | ✅ |
| Excel / Word 课表导入 | ✅ | ✅（拖拽或选文件） |
| 粘贴文本导入 | ✅ | ✅ |
| 数据本地保存 | wx.storage | localStorage |
| 课前页面提醒（震动+声音+横幅） | ✅ | ✅ |
| 系统级提醒（关掉应用也响） | `wx.addPhoneCalendar` 写入系统日历 | **导出 `.ics` 导入系统日历** |
| 后台通知 | 订阅消息（需后端） | **Web Notification**（需 HTTPS + 用户授权） |
| 添加到主屏幕 / 离线可用 | — | ✅（PWA，HTTPS 下） |
| 需要 AppID / 审核 / 上传 | 需要 | **不需要** |
| 换手机迁移数据 | 不支持 | 支持（导出/导入 JSON 备份） |

### 关于"关掉页面也能被提醒"

网页不像小程序那样能常驻后台，所以网页版用了两条路保证不漏课：

1. **浏览器通知**：在「设置 → 申请通知权限」授权后，页面在后台（标签页未关闭）时仍能弹系统通知
2. **导出 .ics 日历**（推荐）
   「设置 → 导出整学期课程到日历」会下载一个 `.ics` 文件，用手机打开并"全部添加"到系统日历。
   之后**即使完全不打开网页**，手机也会在课前 20 分钟响铃——这是最可靠的方式。

## 三、目录结构

```
web/
├── index.html            页面骨架
├── manifest.json         PWA 清单（图标、名称、启动方式）
├── sw.js                 Service Worker（离线缓存）
├── standalone.html       单文件版（构建产物）
├── css/app.css           样式（移动端优先 + 深色模式）
├── icons/                PWA 图标 192 / 512 / maskable
└── js/
    ├── wx-shim.js        浏览器版 wx API（存储/震动/提示音），让小程序代码零改动复用
    ├── bundle.js         从 miniprogram 打包来的核心逻辑（构建产物，勿手改）
    ├── ics.js            .ics 日历生成与下载
    ├── ui.js             Toast / 弹层 / 确认框
    └── app.js            主应用：路由 + 五个视图 + 提醒
```

**构建产物**（改了 `miniprogram/utils` 或 `miniprogram/data` 后需要重新生成）：

```bash
node tools/build-web.js        # 重新打包 web/js/bundle.js
node tools/build-standalone.js # 重新生成 web/standalone.html
```

## 四、和微信小程序版的关系

```
miniprogram/config  ┐
miniprogram/data    ├──(tools/build-web.js 打包)──> web/js/bundle.js
miniprogram/utils   ┘                                    │
                                                         ▼
                                     web/js/app.js（只负责界面与浏览器能力）
```

- **共用**：课表引擎、空教室算法、Excel/Word/CSV 解析、智能识别、提醒判定逻辑
- **各自实现**：存储（wx.storage ↔ localStorage）、提醒（系统日历 ↔ .ics / Notification）
- `miniprogram/` 目录**保留未删**，你可以继续用小程序版，两边数据互不影响

一致性由 `tools/test-web.js` 保证：它会加载打包后的 bundle，
并与直接运行源码的结果做逐项比对。

## 六、常见问题

**Q：手机扫码打不开？**
1. 确认手机和电脑连的是**同一个 WiFi**
2. 确认电脑防火墙放行了 8080 端口（Windows 首次运行 Node 服务会弹窗询问，要选"允许"）
3. 二维码里的地址是不是 `192.168.x.x`（如果是 `172.x` 的虚拟网卡地址，手机连不上）
4. 换个方式验证：在电脑浏览器打开 `http://localhost:8080` 是否正常

**Q：局域网地址变了？**
路由器 DHCP 会重新分配 IP。重新跑 `node tools/make-qrcode.js` 即可生成新的二维码；
想固定地址可在路由器里给电脑绑定静态 IP。

**Q：数据会丢吗？**
数据存在浏览器的 localStorage 里。**清理浏览器数据 / 换浏览器 / 换设备会丢**。
建议定期用「设置 → 导出备份」下载 JSON 文件，换设备时「导入备份」恢复。

**Q：能离线用吗？**
部署到 HTTPS 后可以（Service Worker 会缓存）。局域网 http 或 file:// 下不行，
但课表数据本身在本地，只要页面能打开就能看课表。

**Q：为什么没有"微信登录/同学共享课表"？**
网页版刻意保持无后端、纯本地，不需要注册也不上传任何数据。
如果需要多人共享，可以部署 `server/` 里的后端（原本给小程序订阅消息用的）。
